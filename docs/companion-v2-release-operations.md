## Controlled import, deployment and rollback

The approved bundle's version directory is the input to the already prepared operator-only `market.release_publisher`. Use the dedicated rootless tool image and inactive `compose.companion-releases.yaml` overlay only after deployment gates; pin the verified image digest rather than relying on a mutable development tag. Configure the same public signing pins in the importer and API. Give the importer only the approved read-only incoming bundle and dedicated release volume. It has no network, database/account credentials or collector access, 256 MiB/one CPU, bounded logs and temporary storage. APIs mount the release volume read-only.

The importer independently checks exact bytes, signature and signed version, copies immutable assets/provenance, records a durable audited intent, atomically changes `current.json`, and records completion. Previous versions, proof and audits remain intact. Changed immutable provenance is rejected. Admission limits fail closed and never prune old files. A retry is idempotent. `rollback VERSION --actor OWNER` re-verifies an existing installer and changes only the release pointer; it preserves all versions and never forces clients to downgrade.

Production deployment remains a separate gate: fresh PostgreSQL backup/checksum and isolated restoration, fresh schema-aware original-column fingerprints at recorded cutoffs, passed exact-source CI, compatible additive 0013 migration/API/frontend, approved significant designs, actual signing/installer acceptance, pinned old images and tested rollback. Verify trusted public HTTPS/auth/CSRF/preferences/research/admin/devices, permanent download integrity and native pairing/sync afterward. The original worker must retain its start time, only house 114/market 2 at 300 seconds stays enabled, house 110/history remain untouched, and retention stays off. Do not recreate the worker or activate other feeds to publish desktop software.

Owner visual approval is recorded separately. No signing credentials/provider, cost approval, protected-environment approval, owner PC acceptance, signed stable release, production schema migration or v2 frontend promotion is claimed by this engineering preparation.
