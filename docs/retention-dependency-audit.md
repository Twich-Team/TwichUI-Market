# Retention dependency audit — 2026-11-14

Performed before adding the configurable retention engine. Existing ingestion deduplicates snapshots by market/content hash; multiple observations and UTC daily references can share one snapshot. Raw listings and per-variant statistics independently carry retained flags. Snapshot tombstones must remain reusable, and partially removed rows must be cleared before rehydration.

Pricing `values` reconstructs 14/60-day references from last observations per UTC day; all observations/statistics inside the intraday window (minimum 64 days) are protected. `daily_history` reconstructs historical overlays with 60 days of earlier observations: retain the configured daily window **plus 60 days of supporting daily provenance/statistics**. One current snapshot and the latest observation per market remain protected even for disabled/long-idle markets. Referenced snapshots are selected by observation time, never snapshot creation time. Current raw supply and exact per-variant statistics cannot be pruned.

Daily-reference deletion precedes obsolete observation deletion. Observation deletion excludes every retained daily reference and latest market observation. Statistic pruning excludes shared snapshots used by any current, recent or retained daily reference. Raw pruning excludes snapshots referenced by any current or recent-raw observation. Keep snapshot/content-hash tombstones and needed observation payload hashes/namespaces; do not infer sales from disappeared listings.

Desktop signed cursors contain observation IDs. Missing base/target returns existing HTTP409 full-refresh instruction; pruned statistic flags also return409. An old cursor whose daily support was removed must explicitly fail rather than silently recompute changed reference values. Existing Rust client automatically starts a fresh generation on409 while preserving completed offline cache; export remains data only and no contract version changes are planned.

One mutation batch is bounded in rows and transaction duration, sharing the existing ingestion/sync advisory lock. Stages commit separately. Raw/statistic flags turn false before the first partial deletion; a repeated content hash must delete partial remnants before full rehydration. No background historical application is enabled. Policy edits are audited proposals; administrator application requires current preview confirmation, operator approval gate and fresh verified backup state. Dry-run requires no approval and makes no changes.

Backups are PostgreSQL custom archives with SHA256 manifests, restored with constraints into a fresh isolated market_restore database. Rehearse isolated compaction, confirm pricing/sync invariants, and restore an actual populated archive before requesting live policy approval. Schema downgrade refuses removal of nondefault policy or pruning receipts. Recovery after deletion uses full isolated archive restoration and owner-approved service cutover; application rollback cannot recreate deleted history. No VACUUM FULL, global cleanup, database reset or volume deletion is part of live operations.

Estimate candidate logical row bytes using PostgreSQL average row sizes (sampled/catalogue estimates); distinguish database allocated bytes (pg_database_size), table allocation, estimated logical removed bytes and unknown filesystem recoverability. DELETE enables ordinary PostgreSQL space reuse but promises no filesystem shrink. Hourly allocation growth is observed, never extrapolated as a guarantee.
