# 24H and 48H retained-observation history

The authenticated additive REST endpoint is `GET /api/v1/markets/{market}/items/{item}/{exact_variant}/intraday-history?hours=24|48`. It does not reuse daily points, change pricing, alter collection cadence, fetch providers or change retention. Current daily history and desktop exports retain their contracts. Companion bearer scope is not expanded to browse website charts.

The server scans at most 4,097 observation headers within the rolling UTC window, refusing more than 4,096 with an actionable 503 instead of silently truncating. Ordered by retrieval timestamp then ID descending, it chooses the last real recorded observation in each UTC hour. At most 25/49 buckets overlap a rolling 24/48-hour window, because its edge hours can be partial. Exact variant statistics are read by `(snapshot_id,item_id,variant_key)`; PostgreSQL statements have a three-second deadline. Payloads contain at most 25/49 points, never all listing rows.

Each sample retains actual observation time, original observation/snapshot IDs, namespace, payload hash, upstream modification evidence and synthetic flag. Repeated unchanged source checks can produce equal prices in different hours. These are genuine recorded checks, not new completed sales or proof of an upstream content change. Hourly selection does not average polls, overweight frequently checked hours, interpolate missing observations, or substitute daily samples.

Known complete statistics with an absent variant mean observed zero listed supply and null asking prices. A partial/compacted snapshot remains unknown even if remnants survive. Unsupported algorithms remain unknown. No priced points, absent observations and partial history have separate explanations. Synthetic fixture warnings and existing stale/uncertain source indicators remain visible.

Frontend bucket placeholders contain null prices and unknown supply. They are explicitly unobserved hourly buckets, not invented observations. Labels, tooltips and exact-time tables use the player's local timezone, with timezone abbreviations distinguishing repeated DST hours. Original UTC timestamps remain available in provenance. All money is precision-safe integer copper on the wire and in exact tooltip/table formatting; chart coordinates use the existing ECharts numeric renderer and the axis converts copper to gold.

Choosing 24H/48H persists the range in the item URL (`hours`), independently of saved daily preferences. Daily buttons remove `hours` and continue the existing 7D/14D/60D/1Y/10Y queries. The 1Y label still requests 365 days. Reference algorithm `asking-v1-provisional` is unchanged: current quantity-weighted price, and the mean of the last observation's price per eligible UTC day, omitting unpriced days. A reference can exist with only one observed priced day; Deal Finder's separate minimum-coverage filters remain unchanged.

Read-only production probe (not a deployed HTTP endpoint or live chart): current observed item **211780**, exact variant captured in `evidence/usability-reliability/production-intraday.json`. 24H scanned **262** headers and returned **25** points / **13,201 bytes** in **14.4ms**. 48H scanned **539** and returned **49** / **25,164 bytes** in **7.8ms**. These are single warm/operator measurements, not latency guarantees. No production records, configuration, collector or credentials changed. Synthetic HTTP/browser tests separately verify authentication, isolation, windows, sparse sequences, precision, compacted/unlisted/unsupported states, refusal limits and DST/midnight behavior.
