[Current release procedure](companion-v2-release-operations.md) supersedes the historical options below. No provider/cost decision is pending and no paid signing will be requested again.

Tauri updater signatures use a separately generated application key and require no paid Authenticode certificate. They protect update payloads and do not turn an unsigned Windows installer into a verified Windows publisher. The earlier disabled-updater/manual pilot is superseded by the owner’s mandatory secure automatic-update approach; the implementation now pins the dedicated public key and requires version-bound Tauri signatures before explicit-consent installation. Never disable signature verification to allow automatic unsigned payload installation. [Tauri updater signing](https://v2.tauri.app/plugin/updater/#signing-updates)

Windows' policies vary; an unsigned private application may show an unknown-publisher/SmartScreen warning or be blocked entirely. Signing alone does not guarantee immediate SmartScreen reputation either. Record any blocking message during owner PC acceptance rather than disabling global security protections or installing a test root certificate. [Microsoft signing comparison](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)

If paid Microsoft signing is chosen later, individual developers must be in the US/Canada; organisations have broader supported-country eligibility, and the service needs a paid Azure subscription rather than a free/trial subscription. Eligibility is not yet established for this owner. [Microsoft prerequisites](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart), [subscription FAQ](https://learn.microsoft.com/en-us/azure/artifact-signing/faq)

The current prepared publisher checks an exact certificate thumbprint. Microsoft renews certificates daily (72-hour validity) and documents a durable profile-specific EKU. Before enabling that provider, adapt/test issuer/profile identity validation and receipt/pin rotation while retaining timestamp/chain validation, immutable older installers and rollback. Do not advertise the current fixed-thumbprint workflow as already compatible with daily rotation. A provider choice is needed before that integration. [Microsoft certificate lifecycle](https://learn.microsoft.com/en-us/azure/artifact-signing/concept-certificate-management)

The proposed free pilot would retain all successful installed Windows/backend/browser checks and the owner-approved design, use authenticated private distribution with exact installer/source/hash, expose its beta/unsigned/manual-update status, and leave tray actions explicitly unverified until the owner's real PC checklist passes. This paragraph records the earlier manual pilot only. The final owner decision removes Authenticode from mandatory stable/private gates while retaining updater cryptography, Windows/manual acceptance and separate final approval. No additional collector is activated. Production/API compatibility, fresh restored backup and history-preservation checks remain required before any production deployment.
