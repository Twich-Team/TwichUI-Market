# Native Forever owner acceptance

This is a source review candidate, not a public release. Market draft #31 and addon draft #55 must be reviewed together. The installed Windows synthetic tests and desktop Lua measurements cannot establish real game compatibility or frame-time acceptance.

1. Use the reviewed Companion candidate through the established authenticated/signed distribution process only after separate release authorization. Install the paired addon source identified in `contracts/workshop-summary/v1/addon-source.txt`. Retain the existing signed beta.5 and beta.6 installers and player data. This feature is an unpublished beta.7 source candidate.
2. Sign in and select the verified market through the existing account workflow. Open Workshop Market Data. The Companion first tries its remembered installation, then bounded registry/common locations. With multiple candidates or no verified candidate, choose the Forever folder in the native Windows dialog. If it refuses the actual Forever executable, record its fixed version and the diagnostic; do not bypass validation. Current conservative policy expects 1.60.1 metadata, which has not been confirmed on the owner's executable.
3. Confirm **Connect Workshop** once for that installation. Do not download the optional historical archive or enter item identifiers, dates or budgets. Record account identifier, selected region/ruleset/faction/house and server source time without recording bearer tokens.
4. With WoW running, synchronize and verify **Waiting for World of Warcraft to close**. Record the existing root file hash and modification time; they must not change. Close WoW manually and synchronize again. Record the published generation, source observation, partition count/bytes and last successful file-write time from diagnostics. Verify existing SavedVariables/local scans remain intact.
5. Launch the actual Forever client and open Workshop Market. Grant the existing Workshop import consent where applicable. Record the **loaded** generation and compare it with the Companion's published generation. Confirm market/faction, source time, exact server research variants, copper amounts, supply and coverage. Ambiguous variants require a choice; no native-link equivalence is implied. Summary delivery must describe detailed history as unavailable, preserving genuine local/history views.
6. Measure real client startup/first page open, worst validation callback/frame stalls, retained addon memory and GC impact before/after. Export existing diagnostics. Test focused research, repeated updates, logout/login and a previous-generation recovery without changing source preferences or pricing defaults. Confirm Advisor, local competition, crafting queues and AH behavior remain unchanged.
7. Repeat synchronization without a new generation. Verify HTTP 304/content reuse and unchanged file modification time. Retain the actual game generation/source receipts and resource measurements with the owner's acceptance result.
