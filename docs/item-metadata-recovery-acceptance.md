## Implemented behavior

Versioned PostgreSQL provider records retain normalized base-item fields, exact source/build/locale/confidence, per-field provenance and conflicts. Valid primary Blizzard fields win; partial/failed refreshes preserve good metadata. Local projection fills Explorer, Deals, item search/details and plain tooltip components. All client data comes from authenticated Market APIs/local media. An additive scoped desktop catalog read endpoint leaves the existing v1 price/sync/export contracts intact. Locale is explicitly en_US; other locales are not falsely inferred.

Administrators can preview and enqueue one-item, missing-item, stale-item and bounded Everloot client-attribute import jobs. Persistent tasks, deduplication, committed budget reservations, crash leases and pause/resume/cancel survive browser departure and process restart. Worker calls are independently bounded, avoid collector locks, honor provider cooldown/Retry-After/negative caches and conditional ETags, and prioritize observed/viewed items. Artwork shares the primary provider budget without starving behind a long name queue. Supplementary providers default disabled; a failed source cannot permanently stall the others.

Data Sources provides configuration, all-provider connection tests, health/cooldown/error states, optional expiry warnings and encrypted key replacement for Everloot/ForeverDB. AES-256-GCM keys live outside SQL. A worker validates a staged encrypted candidate before activation, with revision fencing and the old active key retained on rejection. Admin sessions, CSRF, origin checks, no reflected secret validation errors, AEAD provider binding and atomic encryption-key rotation are verified.
