No real provider keys were read and no provider API quota was consumed. Preserve the existing edition/build validation, source precedence, attribution and encrypted credential lifecycle.

## Implementation choices where contracts are silent

- No guessed fixed UTC reset. Application rolling minute/hour/day guards conservatively retain intersecting buckets: second buckets for minute allowances; minute buckets for hourly/daily allowances (at most 59 seconds extra wait). Existing anchored hour/day counters remain additional guards until their original expiry. This preserves committed usage at upgrade; pre-upgrade individual request times are unavailable.
- Settings live separately from encrypted secrets. Administrator-configured maximums are not provider-reported entitlement. Saving a preset changes nothing until the owner saves the form. Higher-than-documented allowances require acknowledgement; finite application safety caps still apply.
- Provider-returned Retry-After always takes precedence, parsed as seconds or HTTP-date, conservatively handling server Date clock skew. Hostile delays are bounded to 366 days; invalid/past dates fall back to bounded cooldown. 429 backoff doubles from 60 seconds to at most one hour; pacing slows for 15 minutes after the cooldown and returns to configured pace. TheWoWDB resumes with an empty burst bucket. No provider is automatically enabled.
- 503 uses a temporary cooldown (at least 60 seconds, or longer Retry-After). 401/402/403 remain distinct, with at least one hour of access cooldown. They never become item-not-found. Rate-limited work stays queued and other providers remain eligible.
- Only numeric standard RateLimit-Limit/Remaining/Reset (delta seconds) and documented TheWoWDB X-RateLimit-Remaining are observed. Unknown/proprietary shapes stay unknown. Observations include their capture time; application usage and remaining budgets are explicitly estimates covering this application only. No raw headers, bodies or secret values enter rate state.
- The architecture intentionally supports one shared request in flight per provider. Expose this safeguard in advanced settings instead of pretending that configurable parallelism exists. The token bucket bounds provider requests, not records per page. Existing byte and cache bounds still apply even for larger pages.

Verified presets are only ForeverDB's documented free and paid numbers. The hourly safety budgets/minimum intervals selected with them are application choices derived to avoid a tighter local bottleneck, not a newly discovered provider contract. Everloot may be manually configured to its documented authenticated allowance after key validation; its existing conservative values are never silently increased.
