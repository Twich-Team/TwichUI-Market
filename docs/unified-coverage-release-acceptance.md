Production promotion and commodity activation are **pending** exact integrated CI and necessary signed reader acceptance. [Diagnosis and implementation](unified-coverage-plan.md) and [restore preservation receipts](evidence/unified-coverage/restore-after.json) describe the completed gates.

Deployment appends the stable root checkout's `compose.owner-backup-policy.yaml` and `compose.unified-coverage-release.yaml` after the full existing overlay chain. Only `api local-api proxy worker` can be replaced, using `up -d --no-deps --no-build --pull never --wait`; do not start stale migration/dependency services. The source CLI performs bounded live identity verification and applies only the existing Market 2 mapping after gates. Keep `next_check` and 300-second cadence.

Rollback before activation can restore the pinned original images without reversing the additive migration. After activation, keep a source-aware worker/API: a pre-unified worker can publish false commodity absence, and the old API cannot interpret the new coverage. A frontend-only rollback can retain the compatible API/worker. For an urgent incompatible backend rollback, stop the collector and put data routes into maintenance first, preserve the populated schema and every observation, then repair/roll forward to source-aware code. Never downgrade populated coverage tables or restore a dump over production. The known predecessor API, frontend and collector images remain retained, as do the verified compatible images in `integrated-images.json`.

The owner requested removal of accumulated database backups. Recurring backup restart remains disabled; the release's temporary checksummed archive will be removed after acceptance. No historical retention or pruning is authorized or enabled. Signing keys and original signed releases remain protected. Physical-PC toast/tray and addon release acceptance are outside this scope.
