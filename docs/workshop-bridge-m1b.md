## Server and companion details

The additive API is `GET /api/v1/bridge/markets/{id}/manifest?algorithm=...&history_days=2..60`, followed by `/records?cursor=...&generation=...&limit=1..100`. Existing desktop/device authentication is required; browser cookies alone cannot export. Opaque HMAC cursors bind credential, account, market, generation, position and expiry. Source data and daily-close winners are pinned under the existing collection/retention advisory lock, then materialized. Pages read immutable rows; expiry/eviction/incomplete materialization returns an explicit restart, never a mixed snapshot. Cold versioned derivations process at most four retained snapshots per request and return 202 until ready. Missing original evidence returns 409 with the original provisional algorithm as an explicit alternative, never relabeling legacy means as canonical.

Record reads use set-based batches of 100 exact identities across supporting dates. Bounds are 150,000 records, 64 KiB per record/header, 1 MiB per page and 32 MiB canonical generation. Build working data is bounded at 64 MiB encoded records; optional distributions and oldest whole delivered days may be omitted with explicit flags, retaining at least the newest two observed dates when available. Failing bounds publishes nothing; narrower history can be requested. Cache retention is one hour, at most two generations per market/algorithm and eight globally. Pricing derivations are versioned additive evidence, not rewritten observations.

The Alembic revision `bridge_20261115` creates only derivation/materialization tables; it must be applied in a separately authorized deployment. Existing migrations, raw observations, schema-2 desktop cache, API contracts, enabled houses and collector/synchronization schedules are preserved. No live migration was executed.

Manual native export uses the current authenticated profile and verified bootstrap identity, with an explicit canonical/provisional basis selector. Download state is namespaced by origin/account/market/algorithm; schema, future versions, wrong identity, partial or corrupt pages, cancellation, auth failure, network truncation and cursor resets cannot replace completed evidence. SQLite promotion and previous retention share one transaction, including tested SQLITE_FULL rollback. The staging root is explicit, owned and outside game/WTF/SavedVariables trees; symlink/reparse points, broad/ambiguous write ACLs and scope-marker mismatch are refused. Files use fixed TOC and decimal-escaped data assignment, flush/sync, same-filesystem atomic replacement, readback validation and a recoverable Previous.lua. It is never listed in the TOC.
