# Source-aware archive protocol 2

This opt-in archive capability adds commodity coverage boundaries without changing the existing schema-2/schema-3 Workshop bridge or its limits. Request `GET /api/v1/archive/markets/{id}/checkpoint?protocol=2`; page/header protocol and evidence revision are 2. Protocol 1 remains the compatible export for the selected market's original source kind. In a unified regular-auction market, protocol 1 excludes the newly collected commodity records. It retains existing observations, exact regular-auction prices, immutable snapshot identifiers, incremental membership and hashes. Native compact synchronization already supports exact commodity unit prices and requires no schema change.

Protocol 2 includes both feeds. A commodity variant's value additionally carries `source_kind: "commodities"` and `coverage_started_at` (the actual first observed UTC timestamp). Ordinary variants retain the original value shape. These fields participate in canonical record hashes, snapshot digests, page chains and checkpoint metadata. Protocol 1 and 2 use distinct digest revisions. Incremental bases cannot cross protocols and must bootstrap after a capability change. The server does not overwrite old checkpoints or source observations.

The source-aware native reader accepts both versions. Protocol-1 SQLite evidence remains in its original namespace and can still project offline during a protocol-2 download. Protocol 2 uses an additive namespace so different snapshot record digests never overwrite the old regular-only archive. Staging, active and previous membership stay transactional and bounded by the existing disk budget. Saved exact selections retain their original market/account/algorithm key. Unknown or mismatched versions, incomplete source-field pairs, future coverage timestamps and mixed-version pages refuse.

Projection preserves every eligible day in the requested bridge window. Before a commodity's coverage start, the day is `unknown` with null price, supply and listing count. It is not an absence proof. Such points do not contribute to observed/priced reference coverage. Existing ordinary item history, integer-copper algorithms, bridge validation, scoped selection, and publication receipts remain unchanged. The addon already supports unknown points; no addon change is required.

This extension is required for commodity-aware Workshop archive projection: the published protocol-1 reader has no per-item source coverage field and otherwise turns nonmembership in a complete regular-only snapshot into zero supply. Existing beta.5 clients continue to receive their original regular-only archive; publishing a new Companion remains a distinct, verified compatibility release step. No new Companion is published merely by merging server support.

Deterministic PostgreSQL tests validate both wire schemas, v1 exclusion/v2 inclusion and cross-version reset. Rust tests verify exact commodity prices, null precollection points, integrity, resume, offline fallback and original SQLite row preservation. Tests use synthetic prices and do not assert current production listings.
