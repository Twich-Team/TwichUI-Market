# Prepared current-price integrity, version 1

Opt-in sidecar over an **unchanged Contract 3 generation**. Existing summary
versions 1/2/3, prices and history are not redefined. This protocol is development
work; deployment, Companion release and client activation require separate gates.

`GET /api/v1/workshop/markets/{market}/summary/{generation}/prepared/1/{count}`
requires the same authenticated device/Companion access as the summary. Only
counts 16 and 32 are accepted. The response is `{account_id, attestation}`; the
ETag is the quoted attestation ID. Expired/wrong-source generations return 410,
unsupported identity/layout 422, and an unsafe whole projection 409. No partial
projection, pruning or zero-price fallback is permitted. Authorization and Market
binding precede source reads and conditional responses.

The attestation follows `attestation.schema.json`. Its ID is SHA-256 of canonical
JSON with `attestation_id` removed, using the existing canonical JSON rules.
`source_generation_id` must equal the fully validated original v3 manifest ID,
which binds Market/issuer, source observation/freshness/completeness, exact current
descriptors and the original 64 history descriptors. The sidecar does not replace
that manifest or claim stronger digital-signature protection.

Every physical bucket 0..count−1 is present, including empty buckets. Regroup
original thirteen-column current tuples by `item_id % count`, strictly sorted by
`(item_id, variant_key)` with no duplicates. `sha256` and `bytes` describe the
canonical JSON array of this group. No prices are recomputed. Each descriptor
also has a SHA-256 Merkle root over the same ordered tuples:

- Leaf: `SHA256("row" || NUL || canonical(tuple))`.
- Padding: `SHA256("empty" || NUL)` up to the next power of two (at least one).
- Parent: `SHA256("node" || NUL || left_hex || right_hex)`; child hashes are
  lowercase 64-character ASCII hex, not binary digest bytes.
- Pack all nodes in heap order, root first, into one immutable hex string. For
  `n` rows, `size=next_power_of_two(max(1,n))` and proof length is
  `(2*size−1)*64`. Leaves start at one-based heap index `size`.

Membership verifies the requested exact tuple at its committed position. A miss
verifies the adjacent positions and strict key inequalities; at either boundary
verify the one adjacent position. Empty groups require zero rows and the known
empty root. Record counts and positional proofs must match the admitted root:
truncating, reordering or inserting rows cannot establish a false missing result.
Missing membership means `not_observed`, never observed absence or price zero.

The prepared data string contains fixed-width records, using lowercase hex:

| Columns | Widths |
| --- | --- |
| item, exact variant, state | 8, 64, 1 |
| recent, Market, minimum, supply | 10, 10, 10, 14 |
| bound age, confidence, historical reference | 1, 1, 10 |
| 14-day priced, 60-day priced, 60-day observed | 2, 2, 2 |

The record is 135 characters. Only nullable original fields use all `z` characters
for their width; no invented zeroes. Copper is at most 99,999,999,999 and supply
at most 2^53−1. Existing tuple/state/coverage rules remain mandatory. Lua 5.1
integer conversion must split long hex words into chunks safe for Windows
32-bit `unsigned long`; no new native runtime API is assumed.

Data plus packed proof strings are bounded to **4 MiB per physical part / 32 MiB
per generation**, with at most the existing 150,000 source rows. An oversized
prepared projection is refused whole; the existing complete v3 remains usable.
These are explicit engineering bounds, not native performance certification.

The Companion independently validates all source bytes, source metadata and
attestation, recomputes the roots/content IDs, then generates a fixed Lua template
from bounded hex/numeric atoms only. Never interpolate imported identifiers,
expressions, arbitrary strings or paths. Never execute Lua to inspect a file.
Readback must match exact regenerated bytes. The game still authenticates every
returned tuple/miss, uses bounded cooperative work, and rejects a mismatched
layout/source/file before exposing a price.

Generation-independent content IDs permit unchanged artifact bytes. A new root
still binds them to the new source generation; cached prices retain their existing
generation/freshness invalidation. This does not authorize cross-account reuse
or replay of stale metadata. The native publisher must preserve root-last A/B
activation, all 64 historical parts, ownership/unexpected-file refusal and a
fully verified previous compatible generation.

`fixtures/synthetic.json` contains fabricated source bytes plus exact 16/32
attestations, data/proofs, multiple variants, supply-only/unknown records and empty
buckets. Python, native Rust and Lua consumers must independently pass these
vectors and corruption tests. They are not prices for a live installation.


## Physical container transport (summary transport 3)

Prepared attestation v1 and Contract 3 source bytes do not change. Additive
`container_packaging_version=1`, `container_codec=raw-deflate-base64`,
`container_block_bytes=524288`, `current_containers=2`, `history_containers=4`
capabilities require exactly32 logical current partitions and a Containers.lua
TOC entry. Older clients ignore them and retain their supported old transport.
The root uses summary_version3; its original five fields are unchanged. Two
current/four history containers per bank map logical bucket to floor(bucket/16).
Every envelope binds source generation and canonical content ID. Streams contain
fixed `{bytes,payload}` raw-Deflate/Base64 blocks, each at most512KiB output.
Returned records/history still require the original authoritative authentication.
See [bounds, migration and downgrade](../../../docs/performance-containers-13.md).
